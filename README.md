# 입법 영향 분석기 (LIA)

**곧 시행될 법이 나에게 무엇을 바꾸는지, 무엇을 해야 하는지** —
자연어로 묻고, 조문 근거와 함께 답을 받는 서비스.

---

## 무엇을 해주나

법은 시행되기 **전에** 공포된다. 그 사이 "이 법이 나한테 뭘 바꾸지?"를 일반인이 알기는 어렵다.
LIA는 **아직 시행되지 않은 법령**을 골라, 당신에게 미칠 영향과 해야 할 행동으로 번역한다.

자연어로 자유롭게 물으면 된다:

- "주택법 바뀌면 나 전세 계약 어떻게 돼?"
- "나한테 영향 있을 시행예정 법령 찾아줘"
- "이번 개정, 언제까지 뭘 해야 해?"

답은 네 가지로 정리된다:

| | |
|---|---|
| **쉬운 요약** | 이 법이 무엇인지 |
| **무엇이 바뀌나** | 현행 대비 달라지는 조문 |
| **내게 미치는 영향** | 내 상황(전세·직업 등)에 맞춰 |
| **대응 행동** | 무엇을, 언제까지 |

### 예시

> **Q.** "2026년 8월 4일 시행되는 주택법 개정, 전세 세입자한테 뭐가 바뀌어?"
>
> **A.** 사용검사 전 **현장점검을 요청할 권리**가 새로 생깁니다(주택법 제49조).
> 시행일은 **2026-08-04**이며, 시행 이후 사용검사 신청 건부터 적용됩니다.
> — *근거: 주택법 제49조 · 부칙 제3조*

## 믿을 수 있는 답

법률 정보는 틀리면 위험하다. LIA는 "그럴듯한 답"이 아니라 **근거 있는 답**을 목표로 한다.

- **지어내지 않는다** — 신뢰 출처(국가법령정보)에서 확인된 조문만 근거로 쓴다. 근거가 없으면 답하지 않는다.
- **모든 주장에 조문 링크** — 답의 근거를 눌러 원문에서 직접 확인할 수 있다.
- **확인 안 된 법을 구분** — "아직 공포 안 된 법"과 "실재하지 않는 법(소문)"을 다르게 안내한다.
- **법률 자문이 아니다** — 참고용 정보이며, 그 점을 항상 명시한다.

### 왜 그냥 ChatGPT·Claude에 물어보면 안 되나

| 그냥 LLM에 질문 | LIA |
|---|---|
| **모른다** — 곧 시행될 특정 개정은 학습 범위 밖 | 실제 현행 조문을 **검색해** 근거로 씀 |
| **지어낸다** — 그럴듯한 조문 번호를 자신 있게 환각 | **근거 없으면 답 안 함** (지어내지 않음) |
| **어느 개정본인지 못 짚는다** | 버전·변경 조문을 대신 특정 |
| **검증 불가** | 모든 답에 **조문 링크** |

LIA는 LLM의 추론력과 경쟁하지 않는다. 날것의 LLM을 *법률 정보*에 못 쓰게 만드는 문제 —
지식 공백·환각·검증 — 를 푸는 것이 핵심이다.

## 무엇을 다루나 — 시행 대기 법령

세상엔 "언젠가 될지도 모르는" 법안이 많지만, LIA는 **이미 확정돼 시행만 기다리는 법령**만 다룬다.

| | 발의 중인 법안 | **공포 후 시행 대기 법령** |
|---|---|---|
| 확정 여부 | 불확실(통과율 낮음) | **100% 확정** |
| 시행일 | 미정 | **확정일** |
| LIA에서 | 다루지 않음 | **분석 대상** |

통과가 불확실한 법안을 분석하면 *일어나지 않을 일*을 알리게 된다.
시행 대기 법령은 시행일이 확정돼 있어 "언제까지 무엇을 하라"가 비로소 단정적으로 성립한다.

## 개인정보

- **성명·연락처·주민번호를 받지 않는다.** 개인화는 회원가입 시 **자기신고 프로필**
  (이용 목적·나이·직업군·주거형태 등, 전부 선택 입력)로만 한다.
- 지역은 시도 단위까지만, 소득·상세주소는 받지 않는다.
- 최소 수집 원칙을 따르며, 자세한 처리방침은 서비스 오픈 시 제공한다.

## 개발자용

기술 하이라이트:

- **비용 인지 설계** — 자연어 질문을 구조화해 *필요한 만큼만* LLM을 호출한다.
  요약·비교는 미리 계산해 두고, 개인화된 영향·대응 분석만 모델을 부른다.
  변경된 조문만 골라내(실측 137→6조문) 처리량을 줄인다.
- **그라운딩 우선** — 모든 주장에 조문을 인용하고, 인용이 없으면 응답을 차단한다(fail-closed).
- **측정 선행 운영** — Prometheus·Loki·Grafana·Tempo + k6. 동시성 최적화는
  지표로 병목을 증명한 뒤에만 적용한다.

스택: Java 21 · Spring Boot 4.0 · Spring AI 2.0 · PostgreSQL + pgvector · Claude(Opus·Haiku).

내부 설계·결정 이력·컴포넌트 스펙·백엔드·트러블슈팅 문서는 [`docs/`](docs/)에 있다.
현황·기술 스펙·구현 체크리스트는 [`docs/status.md`](docs/status.md), 처음이라면 [`docs/onboarding.md`](docs/onboarding.md)부터.

```bash
cd core && ./gradlew test
```

## 면책

법률 자문이 아닌 **참고용 정보 제공** 서비스다.
모든 결과는 법령 조문·부칙·개정문 등 일차 출처로 역추적 가능하며,
근거가 부족하면 답을 만들지 않고 차단한다.
