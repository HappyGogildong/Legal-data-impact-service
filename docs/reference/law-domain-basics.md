# 법령 도메인 기초 — `eflaw`·`law`·제개정구분

법 전문지식 없이도 파이프라인을 이해하도록, 국가법령정보(law.go.kr DRF)의 핵심 도메인 개념만 정리한다. 필드 단위 카탈로그는 [[law-attributes]], 커넥터 계약은 [[SourceConnector]].

---

## 1. `eflaw` vs `law` — 같은 법의 "미래본" vs "현재본"

커넥터가 쓰는 두 `target`은 **같은 법령을 두 시점**으로 본다.

| target | 무엇 | 우리 용도 | 조회키 | 커넥터 메서드 |
|---|---|---|---|---|
| **`eflaw`** | **시행예정** — 공포됐지만 **아직 시행 전**("미래본") | **분석 대상**(D42) | `MST`(법령일련번호, 버전별) | `fetchPending(mst, efYd)` |
| **`eflaw` 현행 행**(`nw=3`) | **현행(시행중)** — **오늘 효력 있는** 본문("현재본") | **diff 기준선** | `LID`(법령ID, 버전 불변) → 그 행의 `MST`+시행일 | `fetchCurrent(lawId)` |

- `eflaw` = "이 법이 **곧 이렇게 바뀐다**"
- 현행 행 = "이 법이 **지금은 이렇다**"
- 둘을 **대조(diff)** 해 "무엇이 바뀌나"를 뽑는다. 같은 `lawId`로 양쪽을 조회한다.

> **`target=law` 가 아니다(D76).** API 안내서상 `law` 는 "현행법령(**공포일**)", `eflaw` 는 "현행법령(**시행일**)"이다. **단계적 시행**이면 한 공포(같은 MST)에 시행일별 버전이 여럿이다 — 주택법 21902: 2026-09-08 `현행`(제21조제1항만 시행) · 2027-03-09 `시행예정`. `target=law` 는 이 공포본을 **마지막 시행일 기준 본문**으로 줘 아직 시행되지 않은 조문이 섞인다. 그래서 eflaw 목록에서 `현행연혁코드=현행` 행을 찾아 그 시행일로 본문을 받는다([[troubleshooting/006-current-law-by-promulgation-date|006]]).

> **조회키 주의:** 현행본은 반드시 **`법령ID`(LID)** 로 찾는다. `MST`(법령일련번호)는 **버전마다 달라** 시행중↔시행예정 연결에 못 쓴다([[SourceConnector]] 실측).

> **응답 봉투:** 목록(`lawSearch.do`)은 영문 루트 `LawSearch`/`law`, 본문(`lawService.do`)은 한글 루트 `법령`. (현행본이 없으면 현행 목록이 `totalCnt=0` — §3.)

## 2. 제개정구분 — 법령이 "어떻게 생겨났/바뀌었나" (종류)

응답의 `제개정구분명` 값. **현행본 유무**가 diff 기준선 존재 여부를 가른다.

| 구분 | 뜻 | 현행본 있나 |
|---|---|---|
| **제정** (制定) | **새로 만든 법** (기존에 없던 법) | ❌ **없음** (신규라 현재 효력본이 없음) |
| **일부개정** (一部改正) | 기존 법의 **일부 조문**만 고침 | ✅ 있음 — 전형적 diff 케이스 |
| **전부개정** (全部改正) | 기존 법을 **통째로 다시 씀**(같은 법, 내용 전면 교체) | ✅ 있음 |
| **타법개정** (他法改正) | **다른 법 때문에** 딸려 바뀜(직접 개정 아님) | ✅ 있음 |
| **일괄개정** | 여러 법을 **한 번에** 묶어 개정 | ✅ 있음 |
| **폐지 / 타법폐지** (廢止) | 법이 폐지됨 / **다른 법 때문에** 폐지됨 | ✅ 있음(폐지 대상 현행본 존재) |

**실측 분포 (시행예정 938건, 2026-08-19):** 일부개정 566 · 타법개정 307 · **제정 54** · 전부개정 4 · 일괄개정 4 · 타법폐지 3.

## 3. ★ 제정 = 현행본 없음 → diff 기준선 부재 (핵심)

**제정(신규) 법령은 현행본이 없다** — 세상에 없던 법이므로 지금 효력 있는 판이 없다. 그래서:

- `fetchPending`(eflaw)로 **미래본은 정상** 조회된다.
- 현행 목록(`eflaw&LID=&nw=3`)이 **`totalCnt=0`** 을 준다 → `fetchCurrent` 가 `null`. (D76 이전 `target=law` 로 조회할 때는 국가법령정보가 `{"법령": {...}}`이 아니라 **`{"Law": "일치하는 법령이 없습니다. 법령명을 확인하여 주십시오"}`**(영문 루트 + 에러 문자열)를 돌려줬다.)

**이건 오류가 아니라 도메인 상태다** — "현행본 없음 = 개정 전 상태가 없음 = 모든 조문이 신설". [[component-specs]] §1.2의 **DiffBuilder가 `baseline=null`을 '전부 신설'로 처리**하는 이유가 이것이다.

**생생한 예 (2026-10-02 시행, 검찰개혁 세트):**
- **공소청법 [제정]** — 새 법 → 현행본 없음 → 현행 목록 0건
- **검찰청법 [타법폐지]** — 기존 법이 폐지됨 → 현행본 있음 → 현행 행 1건

> **예외:** 제정인데도 현행본이 잡히는 경우가 있다(예: 울산국제정원박람회 지원법). **단계적 시행** 등으로 그 법의 **더 이른 판이 이미 시행 중**이면 현행본이 존재한다. 그래서 "제정=무조건 현행본 없음"으로 단정하지 말고, **판정은 현행 목록의 건수로** 한다(종류로 분기하지 않는다).
