# 화면 계획 (웹 프론트엔드 #14)

> [[feature-spec|기능 카탈로그]] 전체를 화면으로 옮긴 계획. **무엇을 보여주는가**와 화면 간 흐름을 정하고, 시각 디자인·구현 기술은 별도로 다룬다. API 계약: [[service-api-spec]].

## 0. 방향

| 결정 | 선택 | 이유 |
|---|---|---|
| 범위 | 기능 카탈로그 **전체**(알림·구독·이력·북마크·자주 찾는 법령 포함) | 나중에 화면 구조를 다시 뜯지 않게. 백엔드가 없는 화면은 지도에 표시 |
| 첫 화면 | **질문창 중심 홈, 로그인은 필요할 때** | 요약·변경점(Layer A)은 익명 허용(API 명세) — 첫 질문까지 문턱을 낮춘다. 개인화(내 영향·대응 방안)·알림·이력에서 로그인·프로필을 권한다 |
| 기기 | **모바일 우선, 데스크톱 대응** | 주 사용자가 일반 시민. 한 열 흐름 기준, 넓은 화면은 여백·사이드 영역. 조문 좌우 대비는 모바일에서 위아래로 |
| 정보 구조 | **질문 중심 흐름 + 법령 상세 허브** | 분석(한 번 묻고 답함)과 법령(읽기 전용 참조)으로 나뉜 API 구조와 일치. 채팅형은 조문 대비·인용·시행일 선택 같은 구조화 화면을 담기 어렵고, 포털형은 "법 이름 몰라도 자연어로"라는 핵심과 반대 |
| 후속 질문 | **지금 보는 법령 맥락만 이어 간다** | 후속 질문에 그 법령을 `lawRef`로 붙인다(API 기존 필드). 모델에는 이전 답변 텍스트가 아닌 법령 참조만 — 그라운딩(D08)·답변 캐시(D51)·최소수집(D41) 유지. 탭 안에서만 유지, 서버 비저장 |
| 대응 방안 | **구조화 상황 확인 + 자유 입력 사실 추출로 반복 고도화**(자유 입력은 다음 단계) | 대응 방안은 사용자의 구체 상황(갱신일·신고 여부 등)에 따라 갈려 한 번의 질문으론 답이 두루뭉술하다. 법령 적용 조건(경과조치·적용 대상·기한 조항)에서 나온 질문으로 상황을 확인하고, 자유 입력은 사실만 뽑아 사용자 확인 후 같은 칸에 채운다. 모델에는 **확인된 상황 사실과 근거 조문만** — 대화 원문은 넘기지도 저장하지도 않는다 |

> 대응 방안 상황 확인은 화면만의 결정이 아니다 — 분석 API에 상황 질문 필드와 재생성 API가 필요하다. **구조화 질문 + 대응 방안 재생성은 D71 로 결정**했다(Layer B 가 질문을 함께 냄). 적용 조건을 Layer A 선계산(#38)으로 미리 뽑는 확장과 **자유 입력 사실 추출은 다음 단계**.

### 내비게이션
- **모바일** — 하단 탭 **홈 · 알림 · 내 정보**. 알림 탭에 읽지 않은 수. 로그인 전에 알림·내 정보를 누르면 로그인(S07)으로.
- **데스크톱** — 같은 세 항목을 상단 바에. 홈이 아닌 화면은 상단 바에 작은 질문창.
- **하단 공통 영역** — "법률 자문이 아닌 참고 정보" 면책 문구와 처리방침 링크를 모든 화면에.

### 공통 요소

| 요소 | 내용 |
|---|---|
| 인용 칩 | "주택법 제18조" 같은 조문 근거. 누르면 법령 상세(S05)의 해당 조문으로 |
| 시행일 배지 | 시행일과 D-N. 같은 법령에 시행예정본이 여럿이면 표시(D43) |
| 법령 맥락 표시 | "지금 보는 법령: 주택법 (2026-08-04)" — 닫을 수 있고, 후속 질문에 `lawRef`로 붙는다 |
| 미충족 안내 카드 | 답을 채우지 못한 차원(`unmet`)의 사유별 다음 행동. 예: "프로필이 필요해요 → 로그인·프로필", "아직 분석 준비 중인 법령이에요" |
| 불확실성 표시 | 근거가 약한 부분을 차원별로 |
| 분석 대기 상태 | 수 초~수십 초 걸리므로 "법령 확인 중 → 분석 중" 단계를 보이고, 결과 차원이 하나씩 채워진다 |
| 로그인 유도 흐름 | 개인화 버튼 → 로그인(S07) → 동의(S08) → 프로필(S09) → **원래 보던 화면으로 복귀** |

## 2. 질문·결과 화면 (S01~S03)

### S01 홈
- **질문창** — 아래에 예시 질문 칩 2~3개(예: "주택법 바뀌면 전세 계약 어떻게 돼?", "곧 시행되는 근로 관련 법 있어?"). 보내면 응답에 따라 화면이 갈린다:

  | 응답 | 화면 |
  |---|---|
  | 해소 성공(`RESOLVED`) | S02 |
  | 모호함(`AMBIGUOUS`) | S03 후보 선택 |
  | 미등록(`NOT_FOUND_YET`)·확인 불가(`UNVERIFIED`) | S03 안내 |
  | 법령 발견 질문(LOOKUP) | S04 |

- **곧 시행되는 법령** — D-N이 가까운 순 5개 → S05.
- **자주 찾는 법령** — 주간 상위 5개 → S05, "전체 보기" → S06.
- **로그인 상태** — 목록 위에 **전체 / 내 관련** 탭. 전체는 익명과 같은 목록, 내 관련은 "내 프로필과 관련된 곧 시행 법령"(법령 발견 #19와 연결). 프로필이 없으면 내 관련 탭에 "프로필을 입력하면 내 관련 법령을 골라 드려요". 데스크톱은 같은 탭 + 오른쪽에 새 알림·최근 저장.

### S02 분석 결과
- **상단** — 법령명·시행일 배지 · 같은 법령의 다른 시행예정본이 있으면 "다른 시행일 보기"(그 시행본으로 다시 분석) · 법령 상세(S05) 링크 · ☆ 북마크(법령 단위, D72 — 익명이면 로그인으로, 돌아와도 자동 추가 없음).
- **답변 차원** — 응답에 온 것만, 순서 고정:
  1. **쉬운 요약** — 한 문단 + 인용 칩.
  2. **무엇이 바뀌나** — 바뀐 조문 목록에 개정·신설·삭제 배지, 펼치면 현행↔개정 대비(모바일은 위아래).
  3. **내 영향** — 프로필에 비춘 영향과 근거.
  4. **대응 방안** — 아래.

  각 차원에 인용 칩·불확실성 표시. 채우지 못한 차원은 그 자리에 미충족 안내 카드(로그인 전 → "로그인하면 내 영향을 알려드려요", 프로필 없음 → 프로필 입력, 처리방침 변경 → 재동의, 하루 한도 초과 → 내일 다시, 근거 부족 → 안내만).

  응답에 내 영향·대응 방안이 없으면 답변 차원 카드 아래에 "내 영향·대응 방안 보기" 버튼(D69) — 같은 법령으로 Layer B 요청.
- **대응 방안 — 상황 확인으로 고도화**
  - **할 일 타임라인** — 단계마다 할 일·기한(시행일·경과 기간)·근거 조문.
  - **"상황을 알려주시면 더 정확해져요"**(D71) — 대응 방안 카드 아래, 서버가 낸 상황 질문이 있을 때만. 법령 적용 조건에서 나온 질문 카드 최대 3개(문장 · 근거 칩 → S05 그 조문 · 형식별 입력: 예/아니오/모름 버튼 · 날짜 입력 · 선택지 버튼 + 모름), 버튼 **"대응 방안 확인하기"**(모름이 아닌 답이 1개 이상일 때 활성), 안내 **"답은 이 법령 판단에만 써요. 이력에 저장할 때만 함께 남아요."**.
  - 확인하면 **대응 방안 카드만 다시 생성해 교체**한다(영향 등 다른 차원은 그대로). 상황이 영향을 준 단계는 배지 **"내 상황 반영"** + 강조 테두리 + 설명 한 줄로 표시한다. 재생성은 개인화 하루 한도를 1회 쓴다.
  - **확인된 상황 사실**은 카드 위 칩("계약 체결 2026-11-01 이전: 예")으로 모아 보여 준다 — 칩에서 바로 고치는 편집(✎)은 다음 단계(지금은 아래 질문 카드에서 답을 바꾸고 다시 확인하면 재생성). 답과 재생성 결과는 **탭 세션(sessionStorage, 법령 버전별) 동안만** 유지 — 새로고침·뒤로 가기에도 남고 탭을 닫으면 사라진다. 서버 세션에는 질문만 있고 답은 저장하지 않는다 — 단 대응 방안 재생성이 성공하면 이력 저장용으로 그 분석 항목에 답을 붙여 세션(메모리)에 둔다(D73, 로그아웃·만료 때 사라지고 DB 는 "이력에 저장"을 누를 때만).
  - **안내**: 하루 한도 초과 → 기존 한도 문구 · 근거 부족 → 기존 대응 방안 유지 + **"근거가 부족해 다시 만들지 못했어요"** · 질문 만료(세션에 질문 없음 또는 화면의 질문 묶음 `setId` 가 서버와 달라짐 — 다른 탭·후속 질문이 같은 법령 질문을 덮어쓴 경우) → **"상황 질문이 만료됐어요"** + 버튼 **"다시 받기"**(같은 법령 Layer B 재요청 — 캐시된 분석을 쓰지 않고 새로 불러 서버에 질문을 다시 저장, 한도 1회). 화면은 재생성 요청에 받은 `setId` 를 그대로 돌려보내고, 저장된 답·재생성 결과도 `setId` 단위로 이어받는다. 로그아웃·계정 삭제 땐 탭에 둔 상황 답을 모두 지운다 · 개인화 불가(프로필 없음·재동의) → 프로필 입력·재동의 안내(`PersonalizeAction`).
  - **자유 입력 "내 상황 설명하기" → "이렇게 이해했어요" 카드(뽑은 사실 목록, 항목별 수정·삭제, 버튼 "맞아요")는 다음 단계** — 이번 범위에는 없다(LLM 사실 추출·확인 화면·자유 문장 입력 공격 대응이 함께 필요). 지금은 구조화 질문 카드만.
- **하단** — 후속 질문창(모바일 하단 고정, 법령 맥락 표시와 함께) · "이력에 저장"(D73 — 로그인 필요, 익명이면 로그인으로·자동 저장 없음, 성공하면 "저장했어요 · 이력 보기". 대응 방안을 상황 확인으로 고치면 다시 "이력에 저장" — 누르면 같은 기록을 고친 내용으로 바꾼다)·"시행 알림 받기"(구독, 로그인 필요) · 면책 문구.

### S03 해소 안내 — 분석하지 않고 상황별로 안내 (fail-closed)

| 상태 | 안내 | 다음 행동 |
|---|---|---|
| 모호함 | "어떤 법령인지 골라 주세요" — 후보 목록(법령명·시행일·소관부처), 같은 법령의 시행일이 여럿이면 시행일 선택 | 고르면 그 법령으로 분석 → S02 |
| 미등록 | "시행예정 법령으로 확인되지 않았어요" — 이미 시행 중이거나 아직 공포 전일 수 있다고 설명 | 질문 고치기 · "법 이름 없이 찾기"(S04) |
| 확인 불가 | "법령을 확인할 수 없어요. 정확한 법령명을 알려 주세요" + 예시. 허위 법령 의심이어도 단정하는 말투는 쓰지 않는다 | 질문 고치기 |

## 3. 법령 화면 (S04~S06)

### S04 법령 발견 결과 — 법 이름을 몰라도 찾은 후보 (LOOKUP, #19)
- 상단: 내 질문 + "질문과 관련 있어 보이는 시행예정 법령".
- **후보 카드**(5~10개) — 법령명·시행일 배지·소관부처, **쉬운 요약 첫 문장**(없으면 개정 이유 앞부분 + "요약 준비 중") · **근거 칩**(조문번호·제목 → S05 그 조문 — 발견 결과도 근거를 댄다), 버튼 "이 법령으로 분석"(원래 질문 + `lawRef` → S02)·"상세 보기"(S05).
- 프로필이 있으면 **"내 프로필 기준으로 찾기"** 토글(기본 끔, API 명세: 법령 발견은 조건부로 프로필 사용). 안내 문구: "켜면 프로필 항목이 검색 처리를 위해 외부 서비스로 전송돼요" — 처리 위탁 내용은 처리방침(S15 `/info#privacy`)에 적는다(D70).
- 결과 없음: "관련 시행예정 법령을 찾지 못했어요" + 질문을 다듬는 팁.

### S05 법령 상세 — 인용 칩·홈 목록·발견 결과가 모이는 허브 (`/laws/{lawId}`·`/laws/{lawId}/{efYd}`, #39)
- **헤더** — 법령명·종류(법률·대통령령 등)·소관부처·공포일·공포번호·시행일 배지. 시행예정본이 여럿이면 **시행일 선택**(D43). 국가법령정보센터 원문 링크·☆ 북마크(법령명 줄, 철회 버전에도)·"시행 알림 받기".
- **상태 배너** — 이력·예전 인용으로 들어왔는데 그 버전이 시행됐거나 철회됐으면 "이 시행예정본은 시행되었어요/철회되었어요". 배치(D62)가 행을 보존하므로 예전 인용도 계속 열린다.
- **본문**
  1. 쉬운 요약(선계산, #38)과 개정 이유. 쉬운 요약 옆 "내 영향·대응 방안 보기" 버튼(D69).
  2. 시행 규칙 — 즉시·유예·단계적과 그 근거 문장.
  3. **바뀐 조문** — 변경 배지 목록, 펼치면 현행↔개정 대비와 바뀐 구간 강조. 조문마다 고유 주소(`#art-18`) — 인용 칩이 그 위치로 바로 온다.
  4. 부칙(이번 개정분).
  5. 위임 조항 — "대통령령으로 정하는 사항" 목록, 하위 법령은 아직 정해지지 않았을 수 있다는 안내.
- 하단: **"이 법령에 대해 질문하기"** — 법령 맥락을 붙인 질문창 → S02.

### S06 법령 목록 — 홈 목록의 전체 보기
- 탭 **곧 시행 · 자주 찾는**.
  - 곧 시행: 기간 필터(이번 주·이번 달·3개월).
  - 자주 찾는: 집계 기간(일·주·월), 순위·증감(↑↓). 집계는 횟수만(누가 봤는지 남기지 않음, D41).
  - 공통: 분야 필터(주거·근로·세제 등).
- 행: 법령명·시행일 배지·소관부처 → S05. "더 보기"로 이어 붙인다.
- 백엔드: 시행일 범위 `/laws` 목록(D65) · `/laws/trending`(S5, 자주 찾는 법령 — 다음 하위 프로젝트). 분야 필터는 분류 데이터가 생길 때까지 보류.

## 4. 로그인·동의·프로필 (S07~S10)

인증·프로필·동의·계정 API가 이미 있어 실제 응답(409 재동의, `upToDate` 등)에 맞춘다. 컴포넌트: [[ProfileApi]] · [[ConsentApi]] · [[AccountApi]].

### S07 로그인
- 카카오·네이버·구글 버튼 + "로그인은 내 영향·대응 방안·알림·이력 기능에만 필요해요. 요약·변경점은 로그인 없이도 볼 수 있어요."
- **원래 화면으로 돌아오기** — 로그인 전 돌아갈 주소를 탭에 저장 → 소셜 로그인 성공 후 서버가 프런트 착지 화면(`/login/done`)으로 보내면, 착지 화면이 동의 상태를 보고 동의(S08) 또는 저장한 주소로 이동. 취소·실패 시 안내 후 원래 화면.
- 첫 로그인이거나 프로필 동의가 없으면 → S08.

### S08 동의
- 처리방침 핵심 4줄 요약(수집 항목: 자기신고 속성만 · 목적: 개인화 분석 · 보관·파기 · 철회 방법) + 전문(S15) 링크.
- 필수 체크 2개 "만 14세 이상입니다"·"프로필 수집·이용에 동의합니다" → `PUT /consents/profile`.
- **재동의 모드** — 처리방침 버전 변경(`upToDate: false`) 또는 프로필 저장이 409로 막혔을 때. "처리방침이 바뀌었어요" + 변경 요약 → **"동의하기"** 후 막혔던 저장 재시도.
- **동의하지 않으면** 익명처럼 요약·변경점만 계속 쓸 수 있다고 안내.
- **만 14세 미만** — "개인화 기능을 이용할 수 없어요" + 계정 삭제 경로(14세 이상 전용, D61).
- 알림 이메일 동의는 여기서 받지 않는다 — 알림을 처음 켤 때 따로(S10·S12).

### S09 프로필 입력·수정
- **모든 항목 선택**, 건너뛰기 가능 — "입력할수록 내 영향이 정확해져요".
- 항목: 이용 목적(복수 선택 칩) · 나이(14~120) · 직업 · 고용 형태 · 가구 형태 · 주거 형태 · 거주 시도 — 모두 선택지, 자유 입력 없음(D41).
- 항목마다 **"왜 묻나요"** 한 줄(예: 주거 형태 → "임대차·주택 법령 영향 판단에 써요").
- 저장 `PUT /profile`(전체 교체) → 409면 S08 재동의 후 재시도 → 원래 화면으로.
- 수정 시 현재 값 채움 + 마지막 수정 시각.
- **소득은 프로필에 두지 않는다**(D41 유지) — 소득에 따라 갈리는 법령이면 대응 방안 상황 확인(S02)에서 **그 법령의 기준에 맞춘 구간 질문**으로만 묻고, 탭 세션 동안만 유지·저장하지 않는다.
- **선택지 목록** — 백엔드 enum과 정확히 같아야 하는데 목록 API가 없다. **프런트 상수로 두고 enum 변경 시 함께 바꾼다**(값이 닫혀 있고 드물게 바뀜). 자주 바뀌게 되면 목록 API를 추가.

### S10 내 정보 (모바일 하단 "내 정보" 탭)
- **계정** — 로그인 수단·가입일·로그아웃.
- **프로필** — 입력한 항목 수 요약 · 수정(S09) · **프로필 삭제**(= 동의 철회, 확인 창: "내 영향·대응 방안을 더 볼 수 없어요").
- **동의 상태** — 프로필 동의(버전·일자·최신 여부 → 재동의).
- **설정** — **이메일 알림 받기** 스위치. 이메일 알림은 법령·구독 단위가 아니라 **계정 단위** — 켜면 모든 알림을 로그인 계정 이메일로도 보낸다. 처음 켤 때 IdP 이메일 저장 동의를 받는다(`PUT /consents/notification-email`), 끄면 철회.
- **바로가기** — 구독 관리(S12) · 이력(S13) · 북마크(S14) · 안내(S15). 알림함은 별도 탭.
- **계정 삭제**(맨 아래 위험 영역) — "되돌릴 수 없어요. 프로필·구독·이력·북마크가 모두 삭제되고 로그아웃돼요" 확인 → `DELETE /account` → 로그아웃 상태로 홈.

## 5. 알림·구독·이력·북마크 (S11~S14)

S11·S12 는 **백엔드가 아직 없다.** S13 이력(D73, [[service-api-spec]] §3.9)·S14 북마크(D72, §3.8)는 API가 있다.

### S11 알림함 (모바일 하단 "알림" 탭)
- **목록** — 새 알림이 위, 읽지 않음 구분. 항목: 메시지("주택법 개정이 7일 뒤 시행돼요")·법령명·시행일 배지·받은 시각·**알림 이유**("구독한 법령" / "내 프로필 관련").
- 누르면 읽음 처리 → 법령 상세(S05), 거기서 "나에게 어떤 영향인지 보기"(S02).
- "모두 읽음" · 빈 상태 "아직 알림이 없어요" + "법령 구독하기".
- 기본 채널은 **인앱 알림함**(연락처 미수집, D49). 이메일은 S10 설정에서 켠 경우만(계정 단위, D60·D61).

### S12 구독 관리
- **두 종류** — **법령 구독**(특정 법령의 특정 시행본) · **내 프로필 관련 구독**(프로필에 영향 있는 법령의 시행 임박; 프로필이 없으면 켤 때 S09로).
- **목록** — 법령명·시행일·알림 시점(예: D-7)·만든 날, 알림 시점 수정·해지. 이미 시행된 법령의 구독은 **"지난 구독"**으로 자동 정리.
- **추가 경로** — S02·S05의 "시행 알림 받기" → 시트: 알림 시점(당일·D-1·D-7·D-30). 이메일 수신은 S10 설정(계정 단위).

### S13 이력 (`/me/history`, D73)
- **명시적 저장만** — S02의 "이력에 저장"을 누를 때만. 서버가 보관한 결과로 스냅샷을 만든다(화면이 내용을 바꿔 저장할 수 없다): 질문·결과 전부(요약·변경점·내 영향·대응 방안·근거 조문 원문)·대응 방안 재생성본·실제로 쓴 상황 답.
  - 자동 저장하지 않는 이유: 질문 원문엔 개인 사정이 섞일 수 있다(D41). 사용자가 고르고 언제든 지운다. 저장 항목은 S15 개인정보처리방침 요약과 처리방침(#35)에 적는다 — 버튼 옆에 안내 문구를 두지 않는다.
  - 저장한 뒤 S02 에서 대응 방안을 고치면(상황 확인으로 재생성) 버튼이 다시 "이력에 저장"으로 돌아온다 — 누르면 **새 기록을 만들지 않고 같은 기록(같은 id)의 스냅샷을 고친 내용으로 바꾼다.** 저장 당시 법령 기준(배너 날짜·"법령 갱신됨" 판정)은 그대로.
- **목록** — 질문(두 줄까지)·법령명·저장일·"법령 갱신됨" 배지·삭제(확인 대화상자 — 스냅샷은 다시 만들 수 없어 되돌리기 대신 확인). 진입은 S10 바로가기.
- **상세** — 저장 당시 결과 그대로(S02 화면을 읽기 전용으로: 후속 질문창·상황 질문·보기 버튼·다른 시행일 없음) + "저장 당시(YYYY-MM-DD) 기준이에요" 배너. 그 뒤 법령이 바뀌었으면(내용 변경·시행·철회) "최신 내용으로 다시 분석"(같은 질문 + 가장 이른 시행예정본으로 S02, 상황 질문은 새로 답함) — 시행예정본이 없으면 "법령 상세 보기".
  - 스냅샷으로 남기는 이유: 그 답이 무엇을 근거로 했는지 나중에도 되짚을 수 있어야 한다(그라운딩 책임성).

### S14 북마크 (`/me/bookmarks`, D72)
- **법령 단위** — 같은 법령은 한 줄. 개정이 와도 다시 북마크하지 않는다.
- 목록 — 법령명 · 상태 배지(`D-n 시행예정` / `시행됨 YYYY-MM-DD` / `시행 예정이던 개정 철회` — 보여 줄 버전 기준) → 그 버전의 S05, 해제(★). 추가한 순서 최근 먼저.
- **해제** — 바로 지우고 그 자리에 "북마크를 해제했어요 · 되돌리기"를 화면을 떠날 때까지 둔다(확인 대화상자·타이머 없음).
- 빈 상태 — "관심 법령의 ☆를 누르면 여기에 모여요." + 홈 링크. 진입은 S10 바로가기.
- **구독과의 차이** — 북마크는 보관만. 알림은 구독(S12)과 계정 설정(S10)에서 다루고 북마크 화면엔 알림 문구를 두지 않는다.

## 6. 신뢰·안내·오류 (S15~S16), 흐름, 백엔드 공백

### S15 안내
- **개인정보처리방침** — 버전·시행일·전문(법무 산출물 #35), 이전 버전 목록(재동의 이력 투명성).
- **이용 안내·면책** — 하는 일·하지 않는 일(법률 자문 아님, 시행예정 법령만) · 답변 방식(AI 생성, 모든 주장에 조문 근거, 근거가 약하면 불확실성 표시) · 데이터 출처(국가법령정보센터).
- **데이터 현황** — 법령 정보 마지막 갱신 시각(예: "2026-10-23 04:12 갱신")과 수록 시행예정 법령 수. 사용자에게 데이터 최신성은 곧 신뢰다.
  - 배치 실행 기록에서 **시각·개수만** 내주는 작은 공개 API가 필요하다. 운영 세부(DEAD 수 등)는 Grafana에만([[cloud-infra]] §4).
  - 같은 갱신 시각을 법령 상세(S05) 하단에도 작게.
- **문의** — 오류·잘못된 안내를 알리는 연락처(이메일). 오류 화면(S16)이 이곳을 가리킨다.

### S16 오류
| 상황 | 화면 |
|---|---|
| 없는 페이지(404) | 홈·질문창으로 안내 |
| 서버·네트워크 오류 | "잠시 후 다시 시도해 주세요" + 다시 시도. 법령을 못 찾은 경우는 오류가 아니라 S03 |
| 세션 만료(401) | 로그인이 필요한 동작에서 → S07, 원래 화면으로 복귀 |
| 점검 중 | 배포 시 Caddy가 보여 주는 정적 페이지 |

### 주요 흐름

| 흐름 | 경로 |
|---|---|
| 익명 질문 | S01 → (S03) → S02 → 인용 칩 → S05 |
| 개인화 | S02 미충족 카드 → S07 → S08 → S09 → S02 복귀·재분석 |
| 대응 방안 고도화 | S02 대응 방안 → 상황 확인 → 대응 방안 재생성(반복) |
| 법령 발견 | S01 → S04 → S02 또는 S05 |
| 알림 | S02·S05 "시행 알림 받기" → (로그인) → 구독 → S11 알림 → S05 → S02 |
| 재방문 | S13 이력 → 다시 분석 |
