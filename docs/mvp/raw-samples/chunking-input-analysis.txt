1. 원본 응답의 모양 (청킹 관점에서 중요한 것만)
------------------------------------------------
최상위: {"법령": { 개정문, 법령키, 기본정보, 부칙, 조문, 제개정이유 }}

조문 > 조문단위[] (주택법 이 버전: 139개 = 실조문 127 + 편장절 제목 12, 조문변경여부 "Y" = 2개(제57조·제68조))
  조문 하나의 키:
    조문번호 "57", 조문가지번호(가지조만), 조문여부 "조문"|"전문"(편장절 제목), 조문제목,
    조문내용 "제57조(주택의 분양가격 제한 등)"   ← 제목 줄뿐. 본문이 아니다.
    조문변경여부 "Y"|"N", 조문제개정유형, 조문시행일자, 조문이동이전/이후 "000000"(이동 없음 자리표시), 조문키,
    항[]                                      ← 실제 본문
  항·호·목 중첩:
    항: { "항번호": "①", "항내용": "① 사업주체가 제54조에 따라 …", "호": [ … ] }
    호: { "호번호": "1.", "호내용": "1. 공공택지", "목": [ … ] }
    목: { "목번호": "가.", "목내용": "가. 삭제 <2023.12.26>" }
  ★ 번호 필드(항번호·호번호·목번호)와 내용 필드(항내용…)가 따로 오는데, 내용 필드도 이미 번호로 시작한다.

→ 청킹 전략에 준 사실
  (a) 조문 하나가 법적 의미의 최소 완결 단위이고, 원본도 조문 단위로 구조화돼 있다 → 1조문 = 1청크.
  (b) 조문 안의 자연스러운 경계는 항 → 호 → 목이다 → 긴 조문은 이 경계에서 자른다(글자 수로 중간을 자르지 않음).
  (c) 조문변경여부가 바뀐 조문을 직접 지목한다 → 바뀐 조문만 색인(비용·노이즈 절감).
  (d) 편장절 제목 행(조문여부 "전문")이 섞여 있고 첫 조문과 번호를 공유한다 → 실조문만 청킹 대상.


2. 정본(청킹 입력)과 원본 비교 — 제57조 ①항
-------------------------------------------
원본:   항번호 "①" / 항내용 "① 사업주체가 …"  /  호번호 "1." / 호내용 "1. 공공택지"
정본 text:
    제57조(주택의 분양가격 제한 등)
    ①
    ① 사업주체가 제54조에 따라 … <개정 2021.7.20, 2023.12.26>
    1.
    1. 공공택지
    2.
    2. 공공택지 외의 택지에서 …
    가.
    가. 삭제 <2023.12.26>

★ 관찰 1 — 번호가 두 번 들어간다.
  원인: Normalizer.mergeArticleText 가 LawEnvelope.text(article.get("항")) 로 항 아래 문자열 값을 모두 재귀로
  이어 붙인다 → 번호 필드("①")와 이미 번호로 시작하는 내용 필드("① …")가 각각 한 줄이 된다.
  영향:
   - 글자 수: 코퍼스 전체에서 약 3.4%만 늘어난다(아래 §3-③) → 2500자 분할 기준에는 영향 작음.
   - 줄 수: 바뀐 조문 전체 줄의 약 47%가 "①"·"1."·"가." 같은 번호만 있는 줄이다.
     RAGIndexer 는 "줄 = 항/호/목 단위"로 보고 직전 1줄을 겹치는데, 겹치는 줄이 번호만 있는 줄이면
     오버랩이 사실상 문맥을 전달하지 못한다.
   - 임베딩·LLM 입력에 같은 번호 토큰이 반복된다(노이즈, 토큰 낭비 소폭).
  상태: D75로 수정 — 내용 필드만 한 줄씩 잇고, 번호는 내용이 번호로 시작하지 않을 때만 붙인다.
       원본 2건 전수에서 내용 필드가 번호로 시작하지 않는 경우는 0(항 470·호 443·목 53).
       revision 이 바뀌어 다음 run 이 전 버전을 다시 저장·색인한다(요약 재생성은 summarize, 유료).

★ 관찰 2 — 현행 대비(diffVsCurrent)의 "현행" 쪽에 원본에 없던 줄이 섞인다.
  예: "개정" 한 단어 줄, "2020.8.18, 2021.4.13, …" 날짜만 있는 줄, "4." 다음 줄에 "2" 다음 "4의2. …".
  확인(현행본 원본): 항에 항제개정유형("개정")·항제개정일자문자열(날짜 목록), 호에 호가지번호("2")가 더 붙어 오고,
       같은 재귀 병합이 그것까지 본문에 넣었다. 로컬 기준선 본문 518,817줄 중 번호 줄 227,731 · 메타 줄 14,685.
  영향: 청킹에는 없음(색인은 시행예정 조문만). 생성 단계의 <baseline_diff> 블록과 화면의 현행 대비에 노이즈.
  상태: D75로 수정 — 메타 필드는 본문에 넣지 않는다(가지호 번호는 호내용 "4의2. …"에 있음).

부수 관찰 — target=law(현행본) 응답의 시행일자가 20270309(미래, 공포 제21902호)였고, 로컬에도 status '시행중'
  · effective_date 2027-03-09 기준선 행이 있다. 현행본 API가 "지금 시행 중인 본"이 아니라 최신 공포본을 주는지
  확인이 필요하다(diff 기준선의 정확성 문제 — 이번 기록·D75의 범위 밖).


3. 코퍼스 전체 통계 (로컬, 시행예정 863개 버전)
-----------------------------------------------
① 바뀐 조문의 규모
   SQL: law_versions(status='시행예정')의 payload.articles 중 isArticle 이면서 changed 인 것
   - 시행예정 버전 863개, 실조문 합계 83,084개 중 바뀐 조문 4,487개(5.4%, 약 1/18.5)
     → 주택법 한 건의 137→6 이 코퍼스 전체에서도 같은 규모로 성립한다.
   - 버전당 바뀐 조문: 평균 5.2 · 중앙값 2 · p90 14 · 최대 58
   - 바뀐 조문이 0개인 버전 78개(제정·전부개정 표기 차이 등) → 이 버전들은 요약 청크만 색인된다.

② 바뀐 조문 본문 길이(글자, D75 수정 전 저장본 기준 — 관찰 1의 중복 포함)
   - 4,487개: 중앙값 431 · p90 1,327 · p99 3,842 · 최대 8,469
   - 2,500자 초과 121개(2.7%) → 대부분(97%)은 분할 없이 1조문 1청크로 들어간다.
   - D75 수정 후 추정(번호만 있는 줄·메타 줄을 뺀 값): 중앙값 420 · p90 1,279 · p99 3,667 · 최대 8,107,
     2,500자 초과 113개(2.5%). 조문당 줄(항·호·목) 수: 중앙값 6 · p90 18 · 최대 124.
   - 2,500자 기준 이유: text-embedding-3-small 입력 한도 8,191토큰, 한국어는 음절당 약 2~3토큰.
     최대 8,107자 조문은 분할하지 않으면 한도를 넘는다.

③ 번호만 있는 줄 (관찰 1)
   SQL: 바뀐 조문 text 를 줄로 나눠 '^([①-⑳]|[0-9]+(의[0-9]+)?\.|[가-하]\.)$' 와 맞는 줄을 셈
   - 전체 72,486줄 중 33,875줄(46.7%)
   - 글자로는 약 2,794,311자 중 93,882자(3.4%)

④ 개정 이유(법령 단위 요약 청크의 원천) 길이
   - 중앙값 370 · p90 1,397 · 최대 4,674, 2,500자 초과 6개

⑤ 현재 로컬 색인(vector_store) — 일부만 색인된 상태(전체 색인은 클라우드 배포 뒤)
   - article 청크 4,896개(그중 분할 하위 청크 #k 256개) · summary 청크 869개 · 법령 618개


4. 이 기록으로 설명할 수 있는 청킹 결정
--------------------------------------
- 조문 단위(1조문 = 1청크): 원본이 조문 단위 구조이고, 조문 번호가 인용·평가(Recall@K)의 단위다. 97.5%(수정 후 추정)가 분할 없이 들어간다.
- 바뀐 조문만: 코퍼스 전체에서 5.4%. 바뀌지 않은 94.6%를 색인하지 않아 임베딩 비용·검색 노이즈를 줄인다.
- 긴 조문만 항·호·목 경계로 분할: 113개(2.5%, 수정 후 추정). 원본의 항·호·목 중첩이 자연 경계다.
- 2,500자: 한국어 토큰 비율로 본 입력 한도 안전선.
- 고정 길이 슬라이딩 윈도를 쓰지 않은 이유: 조문 경계를 넘나들면 인용 단위가 흐려지고, 97.5%의 조문은 애초에 자를 필요가 없다.
- D75 수정으로 줄 = 실제 항·호·목 내용 하나가 되어, "직전 1줄 오버랩"이 번호 한 글자가 아니라 앞 항·호의 내용을 겹친다.
- 정리된 설명: docs/mvp/law-api-response-anatomy.md §8.
