# 006 · 시행예정 목록이 `nw` 없이 조용히 0건

| | |
|---|---|
| 유형 | API 통합 · 조용한 실패 |
| 발생 시점 | 2026-11-01 (D76 기준선 수정 중 라이브 스모크) |
| 관련 | D77 · 파일 `core/.../connector/LawConnector.java` · [[LawConnector]] |

## 1. 문제 정의

`LawLiveSmokeTest`·`NormalizerLiveSmokeTest` 가 **모두** 실패했다. 공통점은 첫 줄의 `listPending(오늘+1, +1년, n)` — 목록이 비어 `get(0)` 에서 터지거나 "시행예정 0건" 단언에 걸렸다. **HTTP 200, 오류 봉투 없음, `totalCnt=0`** 이라 커넥터는 "시행예정 법령이 하나도 없다"고 정상 반환한다. 조용한 실패다.

조용해서 위험하다. 배치(`listAllPending`)에서 0건 목록은 `PendingList.of(heads=[], totalCount=0)` → `0 ≥ 0` 이라 **완주**로 판정된다. 그러면 `Discoverer` 가 저장된 시행예정본 전부를 "목록에서 사라짐"으로 보고 `missing_since` 를 찍고, 다른 날 실행에서 PURGE(철회)한다.

## 2. 가설

1. 범위·정렬 파라미터(`efYd`·`sort`) 형식 문제 — 그러나 코드는 8월부터 그대로다
2. OC 권한·쿼터 — 그러나 오류 봉투가 아니라 정상 봉투에 `totalCnt=0` 이고, 같은 OC 로 본문 조회는 된다
3. **API 쪽 기본값 변화** — 목록 필터 파라미터를 생략했을 때의 기본 동작이 바뀌었다

## 3. 메트릭/실측 기반 원인 확인 (근거)

같은 요청에 `nw`(목록 종류: 1 연혁 · 2 시행예정 · 3 현행)만 바꿔 비교했다(2026-11-01):

| 요청 | `totalCnt` |
|---|---|
| `target=eflaw&efYd=20261102~20271102&sort=efasc` (nw 없음) | **0** |
| 위 + `nw=2` | **875** |
| `…&query=자본시장` (nw 없음) | **0** |
| 위 + `nw=2` | **3** (2026-11-13 · 12-09 · 2027-02-04, 모두 `시행예정`) |

2026-08 실측([[SourceConnector]] §획득 2단계)에선 `nw` 없이 같은 꼴의 요청이 899건을 줬다. 코드는 그대로이고 결과만 달라졌으니 가설 3 — **생략 시 기본값이 바뀌었다**(공지는 찾지 못했다). 목록·검색 모두 같은 경로라 둘 다 영향을 받는다.

## 4. 해결 방안 비교

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 목록·검색 요청에 `nw=2` 명시** | 원하는 것(시행예정)을 직접 말한다. `efYd` 가 미래 범위라 빠지는 행이 없다 | ✓ 채택(D77) |
| B. `nw=1,2,3` 전부 받고 커넥터에서 거르기 | 기본값 변화에 가장 둔감 | ✗ 쓸데없는 행으로 페이지·쿼터 낭비, 거름 규칙이 하나 더 생긴다 |
| C. 0건이면 `nw` 를 붙여 재시도 | 호환 | ✗ 기본값이 또 바뀌면 같은 문제. 의도를 숨긴다 |

## 5. 최종 적용·검증

- `LawConnector` — 시행예정 목록(`listPending`·`listAllPending`)과 검색(`searchPending`) 요청에 `nw=2`.

**교훈:** 외부 API 의 **기본값은 계약이 아니다**. 원하는 필터는 파라미터로 직접 말하고, "0건"이 정상 응답으로 오는 경로에선 그 0건이 **판정(사라짐·철회)으로 이어지지 않는지** 따져 본다.
