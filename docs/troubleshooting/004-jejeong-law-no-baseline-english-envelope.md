# 004 · 제정 법령의 현행본 부재 — 영문 `Law` 봉투로 스모크 간헐 실패

| | |
|---|---|
| 유형 | 커넥터 · API 응답 봉투 · 도메인 상태 · **날짜 의존** |
| 발생 시점 | 2026-08-18~19 (라이브 스모크 간헐 실패) |
| 관련 | `LawConnector.fetchCurrent` · `LawEnvelope` · [[law-domain-basics]] |

## 1. 문제 정의

`LawLiveSmokeTest`·`NormalizerLiveSmokeTest`가 **날에 따라** `본문 응답에 '법령' 블록이 없다: [Law]` 로 실패했다. 같은 머신인데(샌드박스 Bash = 개발 PC) 어느 날은 되고 어느 날은 안 됐다.

## 2. 가설

1. 국가법령정보 API가 봉투 키를 `법령` → 영문 `Law` 로 바꿨다(체계적).
2. 샌드박스와 IntelliJ 환경이 다르다.
3. 특정 법령 **데이터 의존**.

## 3. 원인 확인 (probe 실측)

- **환경 차이 아님** — Bash 도구는 개발 PC의 같은 레포·같은 `.env`·같은 OC에서 돈다. 가설 2 기각.
- `listPending(sort=efasc, 1)` 이 고르는 "가장 이른 시행예정 법령"이 **날마다 바뀐다**(`FROM=오늘+1`).
- 일회성 probe로 시행예정 **938건**을 훑어 각 법령의 본문 최상위 키를 `target=eflaw`/`target=law` 각각 관측:
  - `eflaw`(미래본): **전부 `법령`** ✓
  - `law`(현행본): 개정·폐지는 `법령` ✓ / **제정(신규)은 `{"Law":"일치하는 법령이 없습니다..."}`** ✗
- **제정 법령은 현행본이 없다** → `fetchCurrent(target=law)`가 영문 에러 봉투를 받고 `lawRoot`가 던진 것. 첫 시행예정 법령이 제정인 날에만 실패 → **가설 3 확정**(가설 1은 부분적: 봉투가 영문인 건 "없음" 응답 한정). 분포: 제정 54 / 938.

## 4. 해결 방안

`lawRoot`가 `법령`·`Law` 둘 다 받게? **아니다** — `Law`의 값은 파싱 가능한 본문이 아니라 "없습니다" 문자열이다. **현행본 없음은 오류가 아니라 도메인 상태**다("개정 전 상태가 없음 = 전부 신설"). DiffBuilder는 이미 `baseline=null` 을 전부 신설로 처리한다(D42).

## 5. 최종 적용·검증

- `LawEnvelope.hasLawBody(payload)` — `법령` 블록 유무 판별.
- `LawConnector.fetchCurrent` — 블록 없으면 **`null` 반환**(현행본 없음). `fetchPending`(분석 대상)은 그대로 던진다.
- 스모크 2건 — `fetchCurrent==null` 이면 "제정 → 기준선 없이 전부 신설"로 통과(날짜 의존 깨짐도 해소).
- 단위 `LawEnvelopeTest.현행본_없음_봉투를_판별한다` 통과. `[Law]` 예외는 더 이상 발생하지 않는다.

> **라이브 스모크 캐비앗:** 진단 probe가 하루에 API를 과다 호출(~960콜)해 국가법령정보 **일일 쿼터가 소진**됐다 — 이후 본문(`lawService.do`)이 `빈 응답`으로 온다(목록은 정상). 이는 수정과 무관한 외부 상태이며 쿼터 회복 후 스모크가 정상화된다. **교훈 추가: 진단 probe도 호출량을 아껴야 한다**(전량 순회 금지).

**교훈:** "환경 차이"로 보이는 간헐 실패가 실은 **날짜 의존 데이터**일 수 있다 — 재현은 코드가 아니라 *그날의 입력*이 만든다. API 봉투는 케이스별로 언어·구조가 달라질 수 있으니 **종류가 아니라 응답으로 판정**하고, "없음"을 예외가 아니라 **도메인 상태**로 다룬다.
