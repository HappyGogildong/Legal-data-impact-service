# [번호] 사례 제목

| | |
|---|---|
| 유형 | API 통합 / 파싱 / 동시성 / 성능 / … |
| 발생 시점 | YYYY-MM-DD (구현 단계) |
| 관련 | 커밋 `xxxxxxx` · 이슈 #N · 파일 `path` |

## 1. 문제 정의
무엇이, 어떤 조건에서, 어떻게 잘못됐나. **관측된 증상**을 구체적으로(에러·0건·지연·타임아웃 등). 조용한 실패라면 "왜 조용한가"까지.

## 2. 가설
가능한 원인 후보를 나열한다(1개가 아니라 2~3개). 성급한 단정 금지.

## 3. 메트릭/실측 기반 원인 확인 (근거)
가설을 **데이터로** 검증한다 — raw 응답 비교, 지표·트레이스, 재현 스크립트, 실패 테스트. "추정"이 아니라 "증거".

## 4. 해결 방안 비교
2개 이상 대안을 트레이드오프와 함께. 회피책 vs 정공법, 단순성 vs 정확성.

## 5. 최종 적용·검증
채택안과 이유. **수정 후 재현으로 해결을 증명**한다(테스트·재측정). before/after.
